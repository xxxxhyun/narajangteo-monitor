# 나라장터 키워드 모니터링 설정 가이드

매일 저녁 **20:17(백업 21:17)** 에 조달청 공식 API로 나라장터를 조회해서, 사업명에 **카카오톡 · 상담톡 · 상담 · 채팅** 이 들어간 신규 건을 슬랙 채널로 보고합니다.

```
GitHub(매일 저녁 자동 실행) → 공공데이터포털 API 조회 → 키워드 필터 → 슬랙 채널
```

- 조회 대상: 입찰공고(용역·물품), 발주계획(용역·물품), 사전규격(용역·물품)
- 이미 보고한 건은 다시 보내지 않음 (저장소의 `state.json` 에 기록)
- 신규 건이 없어도 "오늘은 없음" 메시지를 보냄 → 정상 동작 여부를 매일 확인 가능
- 내 PC·크롬과 무관하게 GitHub 서버에서 실행되므로 맥북이 꺼져 있어도 동작

준비물 3가지: ① 공공데이터포털 인증키 ② 슬랙 Webhook 주소 ③ GitHub **개인** 계정
설정 시간: 약 30분 (API 승인 대기 시간 제외)

> **어느 GitHub 계정을 써야 하나요?**
> 회사 계정은 GitHub 제공 서버(GitHub-hosted runner) 사용이 제한되어 있어 별도 서버(self-hosted)가 필요합니다. 그래서 **개인 계정**을 권장합니다.
> 다루는 데이터는 누구나 볼 수 있는 공개 조달 정보뿐이지만, 회사 슬랙 Webhook 주소를 개인 계정에 보관하게 되므로 사내 보안 담당자에게 한 번 확인받는 걸 권합니다.
> 개인 계정 비공개(Private) 저장소는 월 2,000분까지 무료이고, 이 작업은 하루 1~2분이라 한 달 60분 이내로 무료 범위 안입니다.

## 1단계. 공공데이터포털 인증키 발급 (API 활용신청)

1. [data.go.kr](https://www.data.go.kr) 에 로그인합니다 (회원가입 필요 시 가입).
2. 상단 검색창에서 아래 **3개 API**를 하나씩 검색해 들어가 **[활용신청]** 을 누릅니다.
   | 검색어 | 비고 |
   |---|---|
   | 조달청_나라장터 입찰공고정보서비스 | 입찰공고 |
   | 조달청_나라장터 발주계획현황서비스 | 발주계획 |
   | 조달청_나라장터 사전규격정보서비스 | 사전규격 |
   - 활용목적: "기타" 선택 후 "자사 솔루션 관련 입찰공고 모니터링" 정도로 작성
   - 개발계정은 보통 **자동 승인**됩니다.
3. **마이페이지 → 개발계정** (또는 데이터활용 → Open API → 활용신청 현황)에서 승인된 API를 누르면 **일반 인증키(Decoding)** 가 보입니다. 이 값을 복사해 메모장에 적어 둡니다.
   - 인증키는 계정당 하나라서 3개 API 모두 같은 키를 씁니다.
   - 승인 직후 1~2시간은 "등록되지 않은 키" 오류가 날 수 있습니다. 정상입니다.

## 2단계. 슬랙 Webhook 주소 만들기

슬랙 채널에 메시지를 넣을 수 있는 전용 주소를 만드는 과정입니다.

1. 알림 받을 슬랙 채널을 정합니다 (예: `#나라장터-알림`, 없으면 새로 만들기).
2. [api.slack.com/apps](https://api.slack.com/apps) 접속 → **Create New App** → **From scratch**
   - App Name: `나라장터 알림` / Workspace: 회사 워크스페이스 선택 → Create App
3. 왼쪽 메뉴 **Incoming Webhooks** → 오른쪽 스위치를 **On**
4. 아래쪽 **Add New Webhook to Workspace** → 1번에서 정한 채널 선택 → **허용**
5. 생성된 `https://hooks.slack.com/services/...` 주소를 복사해 메모장에 적어 둡니다.
   - 워크스페이스 설정상 앱 설치에 관리자 승인이 필요하면, 요청 후 승인되면 이어서 진행하세요.
   - 이 주소를 아는 사람은 누구나 채널에 글을 쓸 수 있으니 외부에 공유하지 마세요.

## 3단계. GitHub 저장소 만들고 파일 올리기

1. [github.com](https://github.com) 에 **개인 계정**으로 로그인
2. 오른쪽 위 **+** → **New repository**
   - Repository name: `narajangteo-monitor`
   - **Private** 선택 → **Create repository**
3. 만들어진 화면에서 **uploading an existing file** 링크(또는 Add file → Upload files) 클릭
4. 받은 파일 중 **`monitor.py`, `config.json`, `README.md`** 3개를 끌어다 놓고 → 아래 **Commit changes**
5. 자동 실행 설정 파일은 숨김 폴더(`.github`) 안에 있어 끌어다 놓기가 잘 안 되므로 직접 만듭니다.
   - 저장소 첫 화면에서 **Add file → Create new file**
   - 파일 이름 칸에 정확히 `.github/workflows/narajangteo.yml` 입력 (슬래시를 치면 폴더가 자동으로 생깁니다)
   - 받은 `narajangteo.yml` 파일을 텍스트 편집기로 열어 내용을 전부 복사 → 붙여넣기
   - **Commit changes** 클릭

## 4단계. 인증키와 Webhook 주소 등록 (Secrets)

코드에 비밀번호를 직접 쓰지 않고 GitHub 금고(Secrets)에 넣어 두는 단계입니다.

1. 저장소 상단 **Settings** → 왼쪽 **Secrets and variables → Actions**
2. **New repository secret** 을 눌러 2개를 등록합니다. (이름은 대소문자까지 정확히)
   | Name | Secret (값) |
   |---|---|
   | `G2B_SERVICE_KEY` | 1단계의 인증키(Decoding) |
   | `SLACK_WEBHOOK_URL` | 2단계의 hooks.slack.com 주소 |

## 5단계. 첫 테스트 실행

1. 저장소 상단 **Actions** 탭 → (처음이면 "I understand my workflows, go ahead and enable them" 클릭)
2. 왼쪽 **나라장터 키워드 모니터링** → 오른쪽 **Run workflow** 버튼
   - `미리보기만` : 체크 (처음엔 슬랙에 안 보내고 확인만)
   - `조회 기간(시간)` : `72` (최근 3일치로 결과를 넉넉히 확인)
   - 초록색 **Run workflow** 클릭
3. 1~2분 뒤 실행 항목을 누르고 **monitor → 나라장터 조회 및 슬랙 전송** 단계를 펼치면 결과 미리보기가 보입니다.
   - 초록 ✓ 이면 성공. 로그에 "조회 실패"가 있으면 아래 문제해결 표 참고
4. 이상 없으면 `미리보기만` 체크를 **해제**하고 한 번 더 실행 → 슬랙 채널에 메시지가 오면 설정 완료입니다.

이후로는 매일 저녁 자동으로 실행됩니다. GitHub 예약 실행은 서버 사정에 따라 5~30분 늦어질 수 있어 실제 도착은 20시 반~21시 전후가 됩니다.

## 운영하면서 바꾸고 싶을 때

**키워드 추가/삭제, 제외어 설정** — 저장소에서 `config.json` 클릭 → 연필(✏️) 아이콘 → 수정 → Commit changes

```json
"keywords": ["카카오톡", "상담톡", "상담", "채팅", "챗봇"],
"exclude_keywords": ["심리상담", "법률상담"]
```
- "상담"은 범위가 넓어 심리상담·법률상담 같은 무관한 공고도 걸립니다. 며칠 받아보고 노이즈가 많으면 `exclude_keywords` 에 추가하세요.
- 특정 조회 대상을 끄려면 `sources` 에서 해당 항목을 `false` 로 바꾸면 됩니다.
- 신규 건이 없을 때 메시지를 받지 않으려면 `"send_empty_report": false`

**실행 시간 변경** — `.github/workflows/narajangteo.yml` 의 `cron` 줄 수정. UTC 기준이라 한국시간에서 9를 뺍니다. (예: 21:30 → `"30 12 * * *"`)

**잠시 멈추기** — Actions 탭 → 왼쪽 워크플로 선택 → 오른쪽 `···` → **Disable workflow**

## 문제해결

| 슬랙/로그 메시지 | 원인과 조치 |
|---|---|
| `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` | 해당 API 활용신청이 안 됐거나 승인 직후 반영 대기. 1단계 3개 API 신청 여부 확인, 1~2시간 후 재실행 |
| `연결 실패: timed out` | 공공데이터포털이 해외(GitHub 서버) 접속을 간헐적으로 느리게 처리하는 경우. 스크립트가 3회 재시도하고, 21:17 백업 실행이 한 번 더 시도합니다. 며칠 연속이면 알려주세요 |
| `INVALID_REQUEST_PARAMETER` 등 기타 오류 | 조달청 API 사양 변경 가능성. 로그 내용을 복사해서 Claude에게 전달 |
| 슬랙에 아무것도 안 옴 | Actions 탭에서 실행 기록 확인 → 빨간 ✗ 이면 로그 확인. `SLACK_WEBHOOK_URL` 오타 여부 확인 |
| 같은 공고가 또 옴 | 공고가 정정·재공고되어 차수가 바뀐 경우(공고번호 뒤 `-001` 등) 새 건으로 보고됩니다 |

## 파일 구성

| 파일 | 역할 |
|---|---|
| `monitor.py` | 조회·필터·슬랙 전송 프로그램 |
| `config.json` | 키워드, 제외어, 조회 대상 설정 (여기만 고치면 됨) |
| `.github/workflows/narajangteo.yml` | 매일 실행 시간 설정 |
| `state.json` | 이미 보낸 공고 기록 (첫 실행 후 자동 생성, 수정 불필요) |
